# 🦊 Rangkuman Arsitektur & Analisis `camofox-browser`

## 1. Apa itu `camofox-browser`?
**`camofox-browser`** adalah **server otomasi peramban *stealth / headless* yang dirancang khusus untuk agen AI (AI agents)**. Proyek ini dikembangkan oleh tim di balik [Jo Inc](https://askjo.ai) dan berfungsi sebagai alternatif tingkat lanjut untuk Playwright atau Puppeteer tradisional yang sering terblokir oleh sistem deteksi bot modern (seperti Cloudflare, DataDome, Arkose, dan Google CAPTCHA).

---

## 2. Mengapa Dibuat? (*The "Why"*)
Pada otomatisasi browser standar (Headless Chrome, Playwright, Puppeteer-extra-stealth):
- **Deteksi Fingerprint**: Trik *stealth* berbasis JavaScript (monkey-patching `navigator.webdriver`, WebGL shim, dsb.) justru sering terdeteksi oleh sistem anti-bot modern karena menyisakan jejak artifisial (*tells*).
- **Konsumsi Token LLM yang Boros**: Mengirim seluruh kode HTML mentah (DOM) ke LLM sangat memakan kuota konteks (context window) dan biaya API.

**Solusi Camofox**:
1. **Patch C++ Engine via Camoufox**: Berdiri di atas **[Camoufox](https://camoufox.com)** (fork browser Firefox). Spoofing fingerprint (`navigator.hardwareConcurrency`, WebGL renderers, AudioContext, WebRTC, geometri layar) ditangani langsung di **level mesin C++**, sebelum JavaScript halaman mana pun sempat membacanya.
2. **Accessibility Tree & Element Refs**: Alih-alih merender dan membaca DOM HTML ribuan baris, Camofox mengekstrak *accessibility snapshot* dan menyematkan ID referensi elemen yang stabil (`e1`, `e2`, `e3`, ...). Ini menghemat hingga **~90% konsumsi token** bagi AI Agent.

---

## 3. Fitur-Fitur Kunci

### 🧩 1. Element Refs & Accessibility Snapshot
- AI Agent meminta snapshot halaman:
  ```http
  GET /tabs/:tabId/snapshot?userId=agent1
  ```
  Menghasilkan pohon aksesibilitas ringkas:
  ```yaml
  [heading] Example Domain
  [paragraph] This domain is for use in examples.
  [link e1] More information...
  [button e2] Submit
  ```
- Agen cukup mengirimkan ref untuk berinteraksi:
  ```json
  POST /tabs/:tabId/click  -> {"ref": "e1"}
  POST /tabs/:tabId/type   -> {"ref": "e2", "text": "kata kunci", "pressEnter": true}
  ```

### ⚡ 2. Search Macros (Makro Pencarian Cepat)
Tidak perlu mengkonstruksi URL pencarian secara manual:
- `@google_search`, `@youtube_search`, `@amazon_search`, `@wikipedia_search`, `@twitter_search`, dsb.
- Khusus Reddit (`@reddit_search`, `@reddit_subreddit`), Camofox langsung mengambil endpoint JSON bawaan Reddit tanpa perlu parsing HTML.

### 👥 3. Isolasi Sesi & Multi-User
- Setiap pengguna (`userId`) memiliki konteks browser terisolasi (*Playwright BrowserContext* terpisah dengan cookie, cache, dan storage mandiri).
- Dilengkapi mekanisme pengelompokan tab (`sessionKey` / tab groups).
- **Auto-Recycle**: Jika kuota tab maksimum per sesi tercapai, tab yang paling lama tidak digunakan akan ditutup otomatis tanpa menyebabkan error ke agen.
- **Hemat Sumber Daya**: Browser otomatis mati (*idle shutdown*) jika tidak ada sesi aktif selama 5 menit (memori saat idle hanya ~40MB), dan menyala kembali secara instan (*lazy launch*) saat ada request masuk.

### 🍪 4. Manajemen Cookie & Persistence
- **Cookie Bootstrap Import**: Mendukung import file cookie format Netscape (misal untuk sesi LinkedIn, Amazon yang sudah login).
- **Profile Persistence**: Menyimpan sesi, cookies, dan localStorage ke folder `~/.camofox/profiles/<hashed-userId>` sehingga login tetap bertahan meski server direstart.

### 🌐 5. Residential Proxy & Auto-GeoIP
- Mendukung proxy standar maupun *backconnect / rotating sticky proxy* (Decodo, Bright Data, Oxylabs).
- Menggunakan fitur GeoIP bawaan Camoufox untuk **menyesuaikan timezone, locale/bahasa, dan koordinat GPS browser secara otomatis** agar cocok dengan IP exit proxy.

### 🖥️ 6. Sistem Plugin Modular
Di dalam folder [plugins/](file:///c:/Users/Caniago/Downloads/Tes/plugins):
- **`plugins/youtube`**: Ekstraksi transkrip video YouTube cepat menggunakan `yt-dlp` (dengan fallback otomatis ke intercept streaming captions di browser jika yt-dlp tidak terpasang).
- **`plugins/persistence`**: Hook siklus hidup penyimpanan state sesi pengguna ke disk (SQLite / JSON).
- **`plugins/vnc`**: Membuka tampilan browser virtual via noVNC (port 6080). Berguna saat manusia perlu login interaktif, bypass 2FA manual, atau menyelesaikan CAPTCHA, lalu mengekspor `storage_state` untuk dipakai agen.

## 5. Model Keamanan & Privasi

1. **Tanpa Hardcoded Secrets**: Tidak ada token, API key, atau private key yang disimpan dalam repositori.
2. **Access Control**:
   - `CAMOFOX_ACCESS_KEY`: Bearer token global untuk memproteksi seluruh endpoint HTTP jika diekspos ke jaringan publik.
   - `CAMOFOX_API_KEY`: Kunci otorisasi khusus untuk endpoint manipulasi cookie.
3. **Sandbox Proteksi File**: Endpoint upload dan cookie memiliki proteksi ketat terhadap celah *directory traversal*.
4. **Telemetri yang Dianonimkan (Privacy-First)**:
   - Pelaporan crash/hang otomatis dikirim ke Cloudflare Worker ([workers/crash-reporter/](file:///c:/Users/Caniago/Downloads/Tes/workers/crash-reporter/)).
   - Domain publik (Google, Amazon, dll.) dilaporkan apa adanya untuk pelacakan bug, tetapi domain privat/internal di-HMAC hash (`site-a1b2c3d4`). Parameter URL, token, cookie, dan IP selalu disaring (*redacted*). Telemetri ini bisa dimatikan dengan `CAMOFOX_CRASH_REPORT_ENABLED=false`.

## 1. Mekanisme Inti Anggaran: Power Points (PP) & Power Level (PL)

Di M&M 3e, karakter tidak memiliki level kelas (*class-less*), melainkan dibuat menggunakan anggaran **Power Points (PP)** yang terikat pada **Power Level (PL)**:

$$\text{Total PP Standar} = \text{PL} \times 15$$
*(Contoh: Hero standar PL 10 mendapatkan 150 PP).*

Web builder ini mengelola anggaran PP ke dalam 5 kategori pengeluaran utama yang dihitung secara dinamis:

$$\text{Total Terpakai} = \text{Abilities} + \text{Defenses} + \text{Skills} + \text{Advantages} + \text{Powers}$$

- **Mode Standar vs Campaign Mode**: Builder memiliki tombol *Campaign Mode* yang memungkinkan pelacakan penambahan/pengurangan PP yang didapatkan selama petualangan (*PP Log*), lengkap dengan tanggal, catatan, dan riwayat revisi.

## 2. Mesin Kalkulasi Trait & Karakter

Builder mengimplementasikan rumus spesifik M&M 3e untuk setiap komponen:

### A. Abilities (Karakteristik Dasar)
- Terdapat 8 atribut: **STR** (Strength), **STA** (Stamina), **AGL** (Agility), **DEX** (Dexterity), **FGT** (Fighting), **INT** (Intellect), **AWE** (Awareness), **PRE** (Presence).
- **Rumus Biaya**: $\text{Rank} \times 2\text{ PP}$.
- **Absent Abilities**: Mendukung entitas khusus seperti Robot/Konstruk (tanpa Stamina) atau makhluk astral/mayat hidup dengan nilai Absent (−10 PP).

### B. Defenses (Pertahanan)
Pertahanan dihitung dari penjumlahan Ability terkait ditambah Rank yang dibeli (1 PP/rank):
- **Dodge** = AGL + Rank tambahan
- **Parry** = FGT + Rank tambahan
- **Fortitude** = STA + Rank tambahan
- **Will** = AWE + Rank tambahan
- **Toughness** = STA + perlindungan dari Powers/Equipment

### C. Skills (Keahlian)

### D. Advantages (Keunggulan)
- Biaya flat 1 PP per rank/advantage.

## 3. Power Builder v2 (Sistem Terkompleks)

- **Fractional Pricing**: Jika Extras dan Flaws menghasilkan biaya per rank kurang dari 1 PP, sistem menerapkan aturan *fractional cost* resmi (1 PP per 2 ranks, 1 PP per 3 ranks, dst.), bukan bernilai 0 atau negatif.

### B. Alternate Effects (Arrays)

#### 🤖 Assistant

Dalam sistem **Mutants & Masterminds 3rd Edition (M&M 3e)**, batasan karakter tidak diatur berdasarkan kuota poin per section (misalnya bebas mengalokasikan berapa pun PP ke Powers atau Abilities), melainkan diatur oleh **Power Level (PL) Limits** dan **Combat Trade-Offs**.

Total anggaran poin awal standar adalah:
$$\text{Total Power Points (PP)} = \mathbf{PL \times 15}$$
*(Contoh: Pada PL 10 standar, anggaran karakter adalah **150 PP**).*

Berikut adalah standar rumus resmi batasan pembelian/angka akhir untuk setiap section:

---

### 1. Offense / Serangan (Powers, Abilities & Advantages)

Batas efektivitas serangan ditentukan berpasangan antara **Akurasi (Attack Bonus)** dan **Daya Rusak/Dampak (Effect Rank)**:

#### A. Serangan yang Memerlukan Attack Check (Targeted Attacks)
$$\mathbf{\text{Attack Bonus} + \text{Effect Rank} \le 2 \times PL}$$

* **Attack Bonus**: Dihitung dari `DEX/FGT + Close/Ranged Attack Advantage + Accurate Extra + Skill (Close/Ranged Combat)`.
* **Effect Rank**: Peringkat Damage (atau Affliction, Weaken, Nullify, dll).
* **Contoh di PL 10 ($2 \times 10 = 20$):**
  - Seimbang: Serangan $+10$ / Efek Rank $10$ (Total $= 20$).
  - *Accurate / Shifted*: Serangan $+14$ / Efek Rank $6$ (Total $= 20$, tipe lincah/akurat).
  - *Powerhouse / Heavy*: Serangan $+6$ / Efek Rank $14$ (Total $= 20$, tipe lambat tapi mematikan).

#### B. Serangan Area & Perception (Tanpa Attack Check)
$$\mathbf{\text{Effect Rank} \le PL}$$
* Jika kekuatan tidak memerlukan lemparan dadu serangan (misalnya: *Area Damage* ledakan, atau *Perception Ranged* yang otomatis mengenai target yang terlihat), efek rank-nya **tidak boleh melebihi nilai PL itu sendiri**.
* Di PL 10: Efek Area / Perception maksimal **Rank 10**.

---

### 2. Defenses / Pertahanan

Pertahanan diatur berpasangan menggunakan sistem **Trade-off** (maksimal penjumlahan kedua stat adalah $2 \times PL$):

| Pasangan Pertahanan | Rumus Batas Maksimum | Penjelasan |
|---|---|---|
| **Dodge + Toughness** | $\mathbf{\text{Dodge} + \text{Toughness} \le 2 \times PL}$ | Melindungi dari serangan jarak jauh (*Ranged*). |
| **Parry + Toughness** | $\mathbf{\text{Parry} + \text{Toughness} \le 2 \times PL}$ | Melindungi dari serangan jarak dekat (*Melee/Close*). |
| **Fortitude + Will** | $\mathbf{\text{Fortitude} + \text{Will} \le 2 \times PL}$ | Ketahanan fisik internal (racun/penyakit) vs ketahanan mental/jiwa. |

* **Catatan Toughness**: Toughness tidak dibeli langsung per rank seperti defense lainnya, melainkan diperoleh otomatis dari **Stamina**, kekuatan **Protection**, atau advantage **Defensive Roll**. Nilai akhirnya tetap harus patuh pada batas $\text{Dodge/Parry} + \text{Toughness} \le 2 \times PL$.
* **Contoh di PL 10 ($2 \times PL = 20$):**
  - Karakter *Speedster*: Dodge/Parry $15$, Toughness $5$ ($15 + 5 = 20$).
  - Karakter *Brick / Tank*: Dodge/Parry $6$, Toughness $14$ ($6 + 14 = 20$).
  - Karakter *Mystic*: Fortitude $7$, Will $13$ ($7 + 13 = 20$).

---

### 3. Skills (Keterampilan)

Batas total bonus kemampuan untuk setiap keterampilan adalah:
$$\mathbf{\text{Total Skill Modifier} \le PL + 10}$$

$$\text{Total Skill Modifier} = \text{Ability Modifier} + \text{Skill Ranks} + \text{Bonus Lain (Advantage/Item)}$$

* **Contoh di PL 10 ($10 + 10 = 20$):**
  - Bonus akhir keahlian tidak boleh lebih dari **$+20$**.
  - Jika karakter memiliki Intellect $+4$, maka rank skill *Investigation* yang boleh dibeli maksimal adalah **16 rank** ($4 + 16 = 20$).
* Biaya: **1 PP = 2 ranks** (atau 0.5 PP per rank).

---

### 4. Abilities (Karakteristik Dasar)

Secara aturan dasar buku M&M 3e:
$$\mathbf{\text{Ability Rank} \le PL}$$
*(Karakter dapat membeli Ability lebih tinggi hingga batas $PL + 10$ hanya jika tidak melanggar batasan turunan defense dan attack-nya).*

* **Implikasi Turunan**:
  - Jika Anda membeli **Stamina 12** di PL 10, Toughness dasar Anda otomatis bernilai $12$.
  - Akibatnya, Dodge dan Parry Anda maksimal hanya boleh dibeli hingga **Rank 8** ($12 + 8 = 20$).
  - Jika Anda membeli **Fighting 12**, Close Attack Anda bernilai $+12$ dan Parry bernilai $12$. Ini membatasi Damage jarak dekat maksimal $8$ dan Toughness maksimal $8$.

---

### 5. Advantages (Kelebihan / Bakat)

Sebagian besar Advantage adalah nilai biner (1 rank = 1 PP). Namun untuk **Ranked Advantages**:
* Advantage yang memberikan bonus pertahanan (seperti **Defensive Roll**) dibatasi oleh rumus $\text{Dodge/Parry} + \text{Toughness} \le 2 \times PL$.
* Advantage yang memberikan bonus serangan (seperti **Close Attack**, **Ranged Attack**) dibatasi oleh rumus $\text{Attack} + \text{Effect} \le 2 \times PL$.
* Advantage yang tidak terikat combat cap (seperti **Equipment**, **Benefit**, **Languages**, **Well-Informed**) dibatasi oleh alokasi Power Points yang tersedia dan persetujuan Game Master (GM).

Kapan pun Game Master (GM) memanfaatkan status rahasia ini untuk menciptakan drama cerita (misalnya: kostum robek dan hampir ketahuan, harus mencari alasan kabur saat rapat kerja untuk menyelamatkan warga, atau alter egonya dicurigai polisi), pemain akan **diberikan Hero Point** secara gratis sebagai kompensasi masalah tersebut.

  3. **Tantangan Logistik & Waktu**:
     Pahlawan harus membagi waktu antara kehidupan sipil normal (pekerjaan, sekolah, hubungan pribadi) dan tugas kepahlawanan tanpa membuat orang lain curiga.

### Penyebab Masalah
Setiap kali ada perubahan pilihan di Power Studio (misalnya memilih efek baru, menambah modifier, atau mengubah rank), fungsi `renderPowerStudio()` sebelumnya melakukan overwrite menyeluruh pada `modal.innerHTML` termasuk elemen `.modal-dialog`. Akibatnya, browser membuat ulang (*remount*) node dialog DOM dari awal, sehingga animasi CSS `@keyframes modalPopIn` terpicu kembali secara terus-menerus dan posisi *scroll* sempat meloncat ke atas.

---

### Solusi yang Diterapkan
Di [`js/components/powerBuilder.js`](file:///c:/Users/Caniago/Downloads/Tes/mm3e-builder/js/components/powerBuilder.js):

1. **Pemisahan Shell Dialog (`ensureStudioShell`)**:
   - Struktur utama `.modal-backdrop` dan `.modal-dialog.power-studio-dialog` hanya dibangun **satu kali** saat modal pertama kali dibuka.
   - Kontainer terpisah dibuat untuk `#pb-header-container`, `#pb-canvas-container`, dan `#pb-inspector-container`.
2. **Targeted Re-render**:
   - Ketika memilih efek, menambah/mengurangi rank, atau memilih modifier dari palet, hanya sub-kontainer di dalam dialog yang diperbarui tanpa membongkar `.modal-dialog`.
   - Animasi pop-up (`modalPopIn`) kini **hanya berjalan 1 kali** ketika dialog pertama kali muncul ke layar.
3. **Scroll Position Retention**:
   - Posisi scroll pada panel modifier dan canvas tetap tersimpan (`scrollTop`) saat Anda berinteraksi, sehingga layar tidak meloncat ke atas saat menambah extras atau flaws.

---

### 1. Modifier Per Rank (`+X PP / Rank` atau `-X PP / Rank`)

Modifier tipe ini **melekat langsung pada efisiensi kekuatan per tingkatannya**. Biayanya dikalikan dengan seluruh rank efek yang Anda beli.

* **Rumus Biaya:**
  $$\text{Total Biaya} = (\text{Base Cost Per Rank} + \text{Extras Per Rank} - \text{Flaws Per Rank}) \times \text{Rank Efek}$$
* **Filosofi Rules:**
  Digunakan untuk peningkatan mendasar yang skalanya terus membesar seiring semakin kuatnya rank efek tersebut.
* **Contoh Extra:**
  * **Increased Range** (`+1 PP/Rank`): Mengubah *Close Range* menjadi *Ranged*.
  * **Area (Burst, Cone, Line)** (`+1 PP/Rank`): Membuat serangan mengenai seluruh target dalam radius tertentu.
  * **Continuous Duration** (`+1 PP/Rank`): Efek bertahan terus tanpa perlu konsentrasi.
* **Simulasi Perhitungan:**
  * Anda membuat kekuatan **Damage 10** (Base: 1 PP/Rank).
  * Ditambahkan Extra **Ranged** (+1 PP/Rank).
  * Biaya per rank menjadi: $1 + 1 = 2 \text{ PP/Rank}$.
  * **Total Biaya = $2 \times 10 = 20 \text{ PP}$**.

---

### 2. Modifier Flat (`+X PP flat`)

Modifier tipe ini **tidak dikalikan dengan rank efek utama**. Biayanya dibayarkan satu kali sebagai biaya tetap tambahan pada total akhir kekuatan.

* **Rumus Biaya:**
  $$\text{Total Biaya} = (\text{Cost Per Rank} \times \text{Rank Efek}) + \text{Total Flat Extras} - \text{Total Flat Flaws}$$
* **Filosofi Rules:**
  Digunakan untuk fitur situasional, kemampuan sekunder, atau utilitas khusus yang sifatnya "on/off" (nyala/mati) dan kualitasnya tidak perlu melipatgandakan seluruh biaya rank kekuatan.
* **Ada 2 Jenis Flat dalam Rules:**
  1. **Unranked Flat (`◆ Flat`)**: Hanya dibeli 1 kali dengan efek biner (ada atau tidak ada).
     * *Contoh:* **Subtle 1** (+1 PP flat — kekuatan tidak kasat mata/tak berbunyi tanpa indera khusus), **Split** (+1 PP flat — serangan bisa dipecah ke 2 target), **Triggered** (+1 PP flat — dipasang seperti ranjau/jebakan).
  2. **Ranked Flat (`★ Ranked Flat`)**: Modifier flat yang memiliki tingkatan rank sendiri secara independen, tetapi **tetap bertarif flat per rank modifier tersebut** (bukan per rank efek utama).
     * *Contoh:*
       * **Accurate** (+1 PP flat per rank Accurate): Memberi bonus roll serang $+2$ per rank. Jika Anda membeli *Accurate 2*, biayanya hanya $+2 \text{ PP flat}$, memberikan total $+4$ Attack Roll.
       * **Penetrating** (+1 PP flat per rank Penetrating): Menembus pertahanan *Impervious* setinggi rank Penetrating yang dibeli.

* **Simulasi Perhitungan:**
  * Anda membuat kekuatan **Damage 10** (Base: 1 PP/Rank = 10 PP).
  * Ditambahkan Extra **Accurate 2** (Ranked Flat: 2 × 1 PP flat = +2 PP flat).
  * Ditambahkan Extra **Subtle 1** (Unranked Flat: +1 PP flat).
  * **Total Biaya = $10 + 2 + 1 = 13 \text{ PP}$** *(bukan $3 \times 10 = 30 \text{ PP}$)*.

## 1. Aturan Dasar Penerapan Modifiers (*Applying Modifiers*)

Modifier mengubah cara kerja suatu efek kekuatan, membuatnya lebih efektif (**Extra**) atau kurang efektif/terbatas (**Flaw**).
- **Rumus Biaya Total**:
  $$\text{Power Cost} = \Big((\text{Base Effect Cost} + \text{Extras} - \text{Flaws}) \times \text{Rank}\Big) + \text{Flat Modifiers}$$
- **Fractional Costs (Biaya Fraksional)**:
  Jika total Flaws mengurangi biaya per rank menjadi di bawah 1 PP, setiap –1 berikutnya menambahkan jumlah rank yang didapat per 1 PP ($1 \text{ PP} : 2 \text{ Ranks}$, $1 \text{ PP} : 3 \text{ Ranks}$, dst., batas umum hingga $1:5$).
- **Partial Modifiers**:
  Modifier dapat diterapkan hanya pada sebagian rank efek (misal: *Damage 7* dengan 4 rank memiliki *Area Burst*, 3 rank sisanya Damage biasa).
- **Flat Modifiers**:
  Modifier bernilai tetap (tidak dikalikan rank), ditambahkan/dikurangkan langsung ke total biaya akhir setelah perhitungan per-rank. Flaw flat tidak dapat menurunkan biaya kekuatan di bawah 1 PP.
